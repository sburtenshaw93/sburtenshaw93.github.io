How I work

  • Start from the issue, not the code — I don't touch production code until I can state the root cause, the existing pattern I'll follow, and what I expect to break. Then one thin slice: failing test, fix, passing test.
  • Every change goes through our SDLC gates — plan, test, build, commit — each writing an evidence artifact. A red gate stops the work; I don't skip a git hook to get a commit through.
  • I run the product against real customer rulebooks and file an issue for every defect I hit — a lot of my shipped work started that way. Around 240 test files written or changed so far.
  • I don't call something fixed, tested, or deployed unless I can show the command and the output that proves it. If I haven't verified it, I say so.

Projects

Flagship project

Minerva — AI-Assisted Budgeting

A personal-finance PWA built around Henry, an assistant that acts rather than comments — flagging warnings and forecasts, splitting receipts into per-category entries, proposing budget rebalances, and answering "can I afford this?" from real data. Henry runs on a propose → approve → log contract: the model's output is never trusted blindly, a server-side validator checks every proposed action, and it fails closed to a deterministic rules engine. Every insight carries a "Why this?" basis, so nothing changes silently.

Node/Express + Postgres behind 30+ owner-scoped endpoints with a durable per-user audit trail. Sign-in is passwordless — passkey-only WebAuthn with hashed recovery codes — hardened against the OWASP Top 10:2025, with Plaid access tokens stored AES-256-GCM encrypted. Ships as an installable PWA with a hand-written service worker and Background Sync, so expenses entered offline flush on reconnect. 596 Vitest tests across 36 files gate every deploy through GitHub Actions, and it meets WCAG 2.1 AA at Lighthouse Accessibility 100.

Flagship project

Themis — AI Deliberation Council

Real-time web app where five AI advisor-agents debate a user's hard question over a publish-subscribe message bus — a hand-rolled in-process bus plus an embedded MQTT broker — refereed by a guarded finite state machine. Every message is recorded to an append-only SQLite event store with point-in-time replay, and a pluggable LLM backend swaps between Claude and Ollama by config. Built on native Node.js 22 built-ins; deployed live over HTTPS.
